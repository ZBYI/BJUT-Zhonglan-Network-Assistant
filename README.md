# 北工大校园网助手

一个面向北京工业大学校园网的 Windows 批处理登录脚本。当前主分支为 **v3.0.0**。

> [!IMPORTANT]
> **首次使用一定先修改账号和密码。**  
> 当前 v3.0.0 中，账号在 **第 13 行**，密码在 **第 14 行**。  
> 账号后面的 **`@campus` 必须保留，不要删除。**

## 快速使用教程

1. 下载 `BJUT-Network-Assistant.bat`。
2. 找到下载好的 BAT 文件，**右键 → 编辑**。  
   Windows 11 如果没有直接看到“编辑”，可以选择“显示更多选项 → 编辑”，或者使用记事本 / VS Code 打开。
3. 找到 **第 13 行**：

```bat
set "account=YOUR_ACCOUNT@campus"
```

只把 `YOUR_ACCOUNT` 替换成你自己的校园网账号，**保留后面的 `@campus`**。

例如：

```bat
set "account=你的校园网账号@campus"
```

4. 找到 **第 14 行**：

```bat
set "password=YOUR_PASSWORD"
```

只把 `YOUR_PASSWORD` 替换成你的校园网密码。

5. 保存文件。建议使用 **UTF-8（无 BOM）** 编码，避免 BAT 窗口开头出现乱码。
6. 双击 BAT 即可运行。

> [!WARNING]
> **不要删除 `@campus`。**  
> 正确格式是：`你的账号@campus`。  
> 只替换 `YOUR_ACCOUNT` 这一部分。

## v3.0.0 做什么

v3.0.0 的目标是：**双击一次，主动切换到中蓝校区符合规则的最强 5G 校园 Wi-Fi，然后自动完成 Portal 登录。**

> [!IMPORTANT]
> v3 当前自动识别的是 **中蓝校区**、名称符合以下格式的 **5G** Wi-Fi：
>
> **`CMCC-BJUT-SUSHE-H数字-5G`**
>
> 例如：`CMCC-BJUT-SUSHE-H1021-5G`

运行后：

```text
双击 BAT
  ↓
读取当前 Wi-Fi
  ↓
当前 Wi-Fi 是否属于 CMCC-BJUT-SUSHE-H数字-5G
  ├─ 是 → 不主动断开
  └─ 否 → 主动断开当前 Wi-Fi
  ↓
扫描附近中蓝校园 Wi-Fi
  ↓
只保留 CMCC-BJUT-SUSHE-H数字-5G
  ↓
选择信号最强的一个
  ↓
自动连接
  ↓
获取 IPv4
  ↓
Portal 自动认证
  ↓
验证 Internet
  ↓
自动退出
```

如果脚本主动断开了原来的非校园 Wi-Fi，但附近没有发现符合规则的中蓝校园 Wi-Fi，v3 会尝试重新连接刚才的原 Wi-Fi。

### 为什么强调“中蓝”和“5G”

脚本不会把所有附近 Wi-Fi 都拿来比较。它先过滤网络名称，**只有符合中蓝校区命名规则并且带 `-5G` 的网络才会参加信号强度比较**。

因此，即使手机热点、其他运营商 Wi-Fi 或其他网络的信号更强，也不会被选中。

下面这种会进入候选：

```text
CMCC-BJUT-SUSHE-H0921-5G
CMCC-BJUT-SUSHE-H1022-5G
CMCC-BJUT-SUSHE-H1023-5G
```

下面这种不会进入候选：

```text
CMCC-BJUT-SUSHE-H1021
手机热点
其他 Wi-Fi
```

## 很重要：脚本显示成功，但 Windows 仍显示“没网”

> [!NOTE]
> **这可能只是 Windows 的 Wi-Fi / 网络状态界面还没有刷新过来。**

脚本完成 Portal 登录后，会自己发起 Internet 连通性检测。如果窗口已经出现：

```text
[成功] 校园网认证成功，网络已连接
```

说明脚本的实际网络检测已经通过。

此时 Windows 右下角的 Wi-Fi 面板、任务栏网络图标或“Internet 访问”状态可能仍暂时显示：

- 无 Internet
- 正在识别网络
- 仍显示旧的网络状态
- Wi-Fi 图标没有立即变化

这是因为 **Windows 网络状态 UI 与实际网络连通状态的刷新并不完全同步**。通常稍等几秒、重新打开 Wi-Fi 面板后会更新。

最直接的判断方式是：

1. 看 BAT 是否已经显示“**校园网认证成功，网络已连接**”；
2. 打开浏览器实际访问网页；
3. 如果网页已经可以正常打开，就说明网络已经可用，不必只看 Windows 图标。

## 版本说明

### v3.0.0 — 主动切换中蓝 5G 校园 Wi-Fi

在 v2 基础上新增：

- 启动时自动读取当前 Wi-Fi；
- 如果当前 Wi-Fi **不是** `CMCC-BJUT-SUSHE-H数字-5G`，先主动断开；
- 再执行 v2 的“扫描 → 选最强 → 自动连接 → Portal 登录”流程；
- 如果断开原 Wi-Fi 后没有找到目标校园 Wi-Fi，会尝试恢复原连接；
- 当前已经连接目标校园 Wi-Fi 时，不会先做无意义断开。

### v2.0.0 — 中蓝校区 Wi-Fi 自动择优版

- 自动扫描附近 Wi-Fi；
- 只筛选 `CMCC-BJUT-SUSHE-H数字-5G`；
- 自动选择信号最强的目标网络；
- 首次连接开放校园 Wi-Fi 时自动创建 Windows WLAN 配置；
- 自动连接后执行 Portal 认证。

### v1.0.0 — 基础 Portal 自动认证版

- 不负责扫描和切换 Wi-Fi；
- 适用于已经连接校园 Wi-Fi 或有线网络的情况；
- 自动获取 IPv4；
- 自动提交 ePortal 认证；
- 自动验证 Internet。

## 常见问题

### 1. BAT 开头出现几个乱码字符

请把文件重新保存为 **UTF-8（无 BOM）**，并保留文件开头：

```bat
@echo off
chcp 65001 >nul
```

### 2. 为什么脚本选择的不是附近信号最强的任意 Wi-Fi

这是设计行为。脚本只在符合：

```text
CMCC-BJUT-SUSHE-H数字-5G
```

的校园 Wi-Fi 之间比较信号，不会选择手机热点或其他非目标网络。

### 3. 为什么当前已经连着校园 Wi-Fi，脚本还会扫描

因为附近可能存在另一个信号更强的目标校园 Wi-Fi。v3 会重新扫描，如果当前已经是最强目标网络，则保持当前连接。

### 4. 第一次连接某个校园 Wi-Fi 为什么会多一个“创建配置”的步骤

这些目标 Wi-Fi 为开放 WLAN。Windows 如果还没有保存对应网络配置，脚本会自动创建一个 WLAN Profile，然后再发起连接。

## 注意事项

- **不要把填写了真实账号和密码的 BAT 上传到 GitHub、网盘、聊天群或发送给其他人。**
- 仓库中的公开版本只保留 `YOUR_ACCOUNT@campus` 和 `YOUR_PASSWORD` 占位符。
- 当前 Portal 地址为 `http://10.21.221.98:801/eportal/portal/login`。如果学校以后调整认证服务器，脚本可能需要同步修改。
- v3 的 Wi-Fi 自动选择规则当前针对 **中蓝校区** 的 `CMCC-BJUT-SUSHE-H数字-5G`。
- 其他校区未匹配到该命名规则时，不会被当作 v3 的自动择优目标。
- 使用者应仅使用本人有权使用的校园网账号和网络。
